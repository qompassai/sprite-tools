# vs-lightshow — native plugin for VoidSprite

`light-show sprite tools` v1.0.0. A native C plugin (VoidSprite SDK v1) for
the light-show companion sprite pipeline: blink/breathing frame filters with
real dialog parameters, plus a sprite-sheet + JSON exporter whose layout is
configurable but defaults to the game's constants.

**Defaults** (match `game/src/waifu/sprite.rs` and the sheets landed in
commit `1139bca`): 96×192 cells, 4 cols × 6 rows, 180 ms/frame, moods
`idle, blush, wink, pout, celebrate, alarmed`.

## What it provides

- **Filter "Light-show: blink eyes"** — squashes two eye boxes vertically by
  a parameterised amount, producing closed-eye variants of a base frame.
  Parameters: `left eye x/y/w/h`, `right eye x/y/w/h` (all 0–8192),
  `blink amount %` (0–100, default 80). Uses only existing pixels, so it
  works for visor characters too (no skin fill needed). Workflow: duplicate
  the idle base frame, run the filter with increasing amounts across the
  duplicates, e.g. 0 → 60 → 100 → 60 for a 4-frame blink.
- **Filter "Light-show: breathing shift"** — shifts a frame vertically by
  `shift px` (−32…32, default 2), replicating edge rows. Apply +2 / 0 / −2 / 0
  across four frame copies for an idle bob loop.
- **Editor action "Light-show: export sheet + JSON"** — packs every frame of
  the current session into `<basename>.png` + `<basename>.json` in the output
  directory. Requires the session to hold at least `cols × rows` frames
  (exports the first `cols × rows`); every frame must match `cell_w × cell_h`
  exactly. Notifications report success or the specific failure.

Filters run inside the host's undo scope, so undo works with no manual
`editorUndoPushLayerState` call. The export action only reads the session —
nothing to undo.

## The JSON sidecar

Honest note: the game does **not** parse any JSON. It builds its Bevy
`TextureAtlasLayout` purely from Rust constants (`game/src/waifu/sprite.rs`).
The sidecar documents the exact pipeline contract (cell size, grid, mood→row
order, frame duration, per-frame rectangles) next to the PNG for tooling and
humans. Layout changes go in the config file, not the code.

## Configuration

`~/.config/voidsprite/lightshow_export.cfg` (`key=value`, `#` comments).
Missing file = defaults. Any parse error aborts the export with a
notification (typo'd keys are rejected, never silently ignored).

```
cell_w=96
cell_h=192
cols=4
rows=6
frame_ms=180
moods=idle,blush,wink,pout,celebrate,alarmed
basename=seraphine_sheet_fullbody
output_dir=/home/phaedrus/lightshow-export   # optional; default ~/lightshow-export
```

## Build

Needs a C17 compiler. `stb_image_write.h` (PNG writer) and
`voidsprite_sdk.h` (SDK v1) are vendored in-tree.

```sh
./build.sh   # builds vs_lightshow.so, runs unit tests under ASan/UBSan
```

## Install

```sh
mkdir -p ~/.config/voidsprite/plugins
cp vs_lightshow.so ~/.config/voidsprite/plugins/
```

VoidSprite loads it at startup ("Loaded plugin: light-show sprite tools").
Filters appear in the filter list; the exporter under editor actions.

## Sources

- VoidSprite SDK: `counter185/voidsprite`, `voidsprite_plugin_sample/voidsprite_sdk.h` (SDK v1)
- `voidsprite_sdk_c.h` is a mechanical C transcription of that header,
  generated by `./gen_c_header.sh` (the upstream header is C++-only:
  default member initializers, bare struct names, `extern "C"`). The
  vendored original is never modified; struct layout is unchanged.
- PNG writer: `nothings/stb`, `stb_image_write.h` (vendored, unmodified)
- Game layout: qompassai/light-show `1139bca`, `game/src/waifu/sprite.rs`
